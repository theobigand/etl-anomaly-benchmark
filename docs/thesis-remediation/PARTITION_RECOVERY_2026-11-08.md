# Recovery of the historical labelled-pool partitions — 2026-11-08

Scope: tasks T088 and T089 for the 100 labelled problems of the pool (36 ADBench, 64 UCI).
The historical protocol and results are unchanged.

## What was recovered, and how

The historical runs recorded the seeds but not the row identifiers of their
train, validation and test partitions. The split (`research.normalise.split`) is a
deterministic function of the cleaned table and the seed: `research/normalise.py` has
not changed its split or cleaning code since the archives were written
(last functional commit 22aadaa, 2026-10-21; the only later edit adds the validation
and test index arrays to the returned dictionary). The memberships were therefore
**recomputed, not retrieved**: `research/recover_partitions.py` writes, for each
problem, the digest of the source file, of the cleaned table and of the labels, and for
every seed the size, anomaly count, prevalence and SHA-256 of the sorted index array
of each partition (`verification/evidence/pool_partitions/`). The index arrays
themselves are regenerated by the same command; they are not stored because the
digests identify them.

## Validation against the archives

For every problem and seed, the deterministic Z-score detector was replayed on the
recomputed partitions through the benchmark code and compared with the archived
per-seed metrics. All 100 problems (500 problem-seed pairs) reproduce the archived
values to 1e-9. A mismatch would be flagged and left unrepaired. The replay is
sensitive to the training rows (center and scale of the rule), the test rows and the
cleaning, so it confirms the partitions that determine the reported numbers for that
detector. It does not confirm the validation rows, which no reported number uses, and
it does not prove that other detectors saw identical rows, only that the shared
split is the one that produced the archived Z-score values.

## Consequences for the checklist

- T088 (prevalence in train, validation and test) and T089 (published seeds and
  reproducible partition IDs) are supported by this evidence, with the qualification
  that the identifiers are recomputed and replay-validated, not originally archived.
- T062 and T063 stay open. The historical `normalise.clean` still makes schema,
  encoding and conflicting-row decisions on the whole table before the split
  (documented earlier); recovering the partitions does not make that path train-only.
  Replaying the studies on the explicit train-only path remains a separate task and its
  results would be exploratory, not a validation of the historical numbers.
- The manuscript methods now state that the identifiers were recomputed and how they
  were checked. The slides are unchanged: no slide describes partition identifiers.
